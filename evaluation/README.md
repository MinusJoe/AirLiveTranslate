# 人工录制与标注材料

`recording_prompts.jsonl` 含 24 条原创录音脚本，每种语言 8 条。它们是测试输入文本，**不是实际录音、真实说话人语料、识别输出或性能结果**。`meaning_checks` 是人工核查要点，不是机器生成的参考译文评分。

`run_template.json` 是结果格式示例，状态为 `not_run`，计时与评分为空。每次真正执行时复制一份，记录提交和环境，然后填写结果。不要把空模板算作一次通过的测试。

## 录制步骤

1. 请熟悉源语言的人自然朗读 `text`，使用其真实日常发音；记录是否以此语言为母语及自述地区发音（均可不填），不用姓名。
2. 每条先正常说，再自然加快至约自己的 1.25 倍、1.5 倍；不要求牺牲清楚度。目标倍数仅作指导，记录实际时长与计算后的说话速率。
3. 含自我修正的脚本按原文读出修正，保留自然停顿；不要先把旧数字删掉。`do_not_split_before` 指出不宜过早认定含义的风险位置，不是朗读指令。
4. 每条录音前后留约 1 秒静音。只录参与者已知晓的测试内容。保留原始采样率/声道和未裁剪版本，裁剪另存，填写处理方式。
5. 按 `prompt_id + speaker_id + speed_condition + take` 命名，例如 `EN03_s01_fast_t01.wav`。此例是命名模板，不代表仓库含有该音频。
6. 人工逐字核对实际录音；若朗读与脚本不同，`reference_transcript` 使用实际说出的内容，不能强行以脚本为金标准。
7. 用同一录音分别测试基线与新实现。额外自然对话真机测试单列，不与固定录音混为同一条件。

建议速率单位：英语为词/分钟，中文和日语为去空白/标点后的字符/秒；数字的书写规范固定。不同语言单位不同，不能横向排序出“哪个语言更快”。

## 场景标签

- `ordinary`：完整短句与自然语义边界。
- `late_negation`：后部否定改变前文含义，防止提前误播。
- `number_correction`：数字或时间自我修正。
- `long_clause`：从句和条件关系，测试等待与上下文。
- `proper_names`：专名/地名，测试真实地区模型差异。
- `enumeration`：快速列举，测试漏项和顺序。
- `repetition`：真实重复与自我更正，不能去重误删。
- `mixed_terms`：常见外语技术词，测试混合词汇而非自动语言切换。

## 结果填写

一个 run 对应固定提交、设备、语言对、地区 locale、提交策略、音频路由和素材。`segments` 的时间均使用同一个时基，单位毫秒；未测的声学出声时间保持 `null`，不可用 TTS 入队时间替填。跳过音频应在 `playback_status` 写 `skipped` 并填原因，字幕内容可独立保留。

参考完整方法：[性能评估](../docs/PERFORMANCE_EVALUATION.md)。录音和含个人声音的实际结果默认不随源码提交；共享前按测试参与者同意范围处理。
