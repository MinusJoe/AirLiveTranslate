# AirPods 周围讲话听译：MVP 需求

状态：需求基线；实现、编译与设备验收状态见 `ACCEPTANCE.md`。

## 1. 用户目标与交付边界

用户将同一副 AirPods 的左右耳都佩戴在自己耳中，希望一侧采集周围人的讲话，另一侧播放译文；启动后尽量不需要拿出手机。首版针对单个近距离发言者的持续听译，不包含两个人各戴一只、两副蓝牙耳机互联、通话音频抓取或多人同时讲话分离。

目标平台为 **iOS 26.0+**。用户测试手机为 iPhone 17、iOS 27.0.1；耳机按本次上下文优先验证 AirPods Pro 3，用户表示固件为最新版本，验收时仍须记录具体版本。目标语言为中文、英语、日语，六个有向语言对分别验收。最低系统版本、目标硬件和声明的语言不等于实际兼容证明。

远场收音 API 从 iOS 26.2 起可用，必须使用系统可用性保护和设备能力检测。iOS 26.0/26.1 应能运行 App，但明确显示远场模式不可用，允许用户主动选择受支持的手机收音备用方案；不得因最低部署版本为 26.0 而虚报远场支持。

交付为可维护的原生 SwiftUI 工程、真实本地语音处理链路、构建说明和验收记录。用户已选择 Codemagic 云构建，应包含对应工作流与签名配置说明；构建配置存在不等于云构建已运行成功。只有经过构建、签名并在设备安装验证后才能称为可安装 IPA；Windows 环境生成源码不等于已生成 IPA。

## 2. 必须诚实表达的能力边界

| 能力 | 产品约束 |
| --- | --- |
| 耳机远场采集 | 请求 `farFieldInput` 前后均检查当前输入路由；区分不支持、支持但未启用、已启用、未知。仅已启用时可显示“远场收音已启用”。 |
| 固定左/右收音 | 提供系统 AirPods 麦克风设置说明。未确认公开 API 可在 App 内设置；不得制作看似可控制硬件的虚假切换。系统固定麦克风设置也不能证明远场处理只用了某个物理麦克风。 |
| 单耳播放译文 | 读取实际录放音路由与输出通道；只有能映射并验证独立左右声道时开放相应选项。单声道、未知映射或路由改变时不得继续声称指定耳播放。 |
| 左右选择的回退 | 无法满足指定侧时停止/阻止该模式，解释原因；用户可明确选择支持的双耳模式。不得静默播放到另一耳或手机扬声器。 |
| 手机麦克风回退 | 必须由用户主动选择，并在运行页清楚展示当前输入。耳机断连不得悄悄继续录手机麦克风。 |
| 环境方向和人声 | 左侧收音不等于只听左侧的人。远场采集不保证隔离指定说话人，也不保证嘈杂环境或任意距离效果。 |
| 原声与译声 | 单耳无译文不等于该耳开启通透模式。首版不承诺单耳独立通透/降噪控制。 |
| 本地能力 | 识别、翻译、合成都须验证可用语言/资源。任一环节需要联网推理时，不得称为离线链路。首版不隐式切换云端推理。 |

## 3. 功能优先级

### P0：首版必须实现

1. **启动检查。** 显示麦克风及所选识别路径需要的授权状态、输入/输出设备、远场状态、单耳能力、语言资源状态。缺失条件应提供可理解的下一步操作。
2. **显式选择语言。** 指定源语言与目标语言；禁止相同语言对开始翻译。短句不依靠自动语言识别。语言选择只列出已实现的选项，并在启动时检查本机能力。
3. **明确选择输出。** 用户指定左耳、右耳或双耳；展示其为设备已支持、待设备检测或不可用。不得使用 UI 选择值代替实际路由状态。
4. **持续处理链路。** 真实采集音频，持续识别，按稳定的语义片段顺序翻译并合成。用户不需要对每句话点击“翻译”。不能只在结束整场录音后翻译，也不能用预置文字冒充麦克风结果。
5. **双语字幕。** 区分识别草稿、已提交原文、翻译中、已完成译文和失败。草稿允许更新，已播报内容不静默改写。识别无有效内容时不生成猜测译文。
6. **开始、暂停、继续、结束。** 暂停/结束停止采集和播报，取消未完成识别/翻译/合成，清空待播队列。恢复开启新处理代次，不播放旧代次结果。
7. **失效与中断。** 路由改变、耳机断连、电话/系统音频中断、权限失效和引擎错误应停止不安全的处理，并显示实际状态。恢复前重新检查能力，避免耳机译文泄露到扬声器。
8. **有界积压。** 翻译与播报队列有明确上限。处理落后时显式提示并暂停收音或进入需要用户处理的状态；不无限占用内存，不悄悄丢弃语义片段，不把摘要当完整译文。
9. **最少留存。** 原始录音和字幕默认只在会话内存中使用。结束后清除，或明确由用户决定保留当前屏幕内容；不得自动持久化原始音频、传往未说明的服务器或把原文写入诊断日志。
10. **清楚的运行反馈。** 显示收音、识别、翻译、播报、暂停、被系统中断和错误。麦克风有电平反馈；不把有电平当成识别成功。开始前提醒用户让在场者知晓收音用途。

### P1：真机验收后再扩展

- 锁屏长时间运行及可控恢复；未完成真机验证前标记为待验证，不承诺全天后台运行。
- 个性术语表、会话导出、可调语速、离线资源管理、延迟与耗电诊断。
- 更积极的增量语义提交：在长句未结束时翻译稳定片段，须防止重复、漏译和否定含义反转。

### 暂不纳入本版

- 声纹身份识别、多人重叠语音分离、自动双向对话、第三方通话音频、两副蓝牙设备自由路由、声音克隆、账号/付费/云端模型接入。

## 4. 关键体验约束

初次使用流程：选择语言 → 说明本地处理与知情收音 → 请求必要权限/准备资源 → 连接耳机并检测 → 选择真实可用输出 → 开始。

源语言、目标语言或输入/输出选择在运行期间不可无序变更。实现可选择先暂停再变更，或禁用相关设置；任何改变都必须淘汰旧处理代次。

提交给翻译和播报的片段必须具有稳定标识与顺序，避免识别草稿修订导致同一句重复播报。取消后到达的回调不得改变新会话 UI 或触发新播报。

“同声听译”表示连续收音和分段输出存在重叠、允许语义等待，不表示零延迟。若首版只处理识别引擎提供的最终片段，应如实称为“连续分段听译”，并记录长句等待限制。

## 5. 成功标准与当前未知项

软件层必须可证明权限拒绝、路由失效、取消、过期回调、顺序和积压控制行为正确。硬件层必须在双耳佩戴、手机放口袋的条件下证明远场启用、指定耳播报和同时录放音成立。

初始性能目标为：在清晰近距离单人讲话条件下，语义片段结束至耳机实际开始译音的中位数争取 1.5–3 秒、P95 不超过 5 秒。该数值是待测目标，不是产品保证；同时记录源片段开始至译音开始的总等待，防止长分段掩盖延迟。

未确认项：AirPods Pro 3 具体固件和设备组合中的远场支持、远场与固定左右麦克风设置的关系、同时收音时左右输出通道、锁屏后的本地翻译/合成可用性、六个语言方向的质量及能耗。
