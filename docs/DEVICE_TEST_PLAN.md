# 真机验收计划

状态：待执行。本文不是测试通过报告。Windows 环境无法运行 Xcode、iOS SDK、AirPods 或签名流程。

## 测试环境记录

- 主测设备：用户提供的 iPhone 17 / iOS 27.0.1；以实际设备设置页为准。
- 耳机：记录具体型号、固件版本、电量，不以“最新”代替版本号。
- 最低系统：iOS 26.0；远场相关 API 要求 iOS 26.2，低版本必须显式阻止该模式。
- 记录 Xcode、SDK、构建号、Git revision（或交付文件哈希）、安装方式。
- 记录设备地区、语音与翻译资源安装状态、单声道音频/左右平衡/空间音频等设置。
- 听力或听感判断最好由两位测试者交叉确认。采集他人讲话前征得其知情同意。

## 分层通过条件

1. 工程层：Mac/Codemagic 上运行纯核心测试和 iPhoneOS 无签名编译；保留原始日志。
2. 安装层：使用有效签名安装到注册设备，或通过 TestFlight 分发。构建成功不等于可安装 IPA 已生成。
3. 音频层：真实远场启用与指定耳侧播放通过，才能宣称此耳机组合支持用户目标。
4. 翻译层：六个方向分别评估，不从单方向推导其他方向。
5. 发布层：所有 P0 用例通过；其余不足必须在产品和发布说明中明确披露。

## P0：能力、路由与隐私

| 编号 | 操作 | 预期结果 / 证据 |
|---|---|---|
| CAP-01 | 不连接耳机，尝试开始 | 明确阻止；不得偷偷改用手机麦克风或扬声器 |
| CAP-02 | 连接耳机但远场 capability 不支持或 extension 为 nil | 区分“不支持”与“未启用”，不宣称远场已开启 |
| CAP-03 | capability 支持，但会话激活后 isEnabled 为 false | 停止启动并给出可操作提示，不只依赖设置请求成功 |
| CAP-04 | 在 iOS 26.0/26.1 构建目标对应设备运行 | 无未保护的新 API 调用；解释远场需要 26.2+ |
| CAP-05 | 开启录音后检查实际输入/输出端口 | 使用同一目标耳机；输出声道能力取自当前路由而非设备名称 |
| SIDE-01 | 选择左耳，播放已知测试音/译文，双耳分别试听 | 右耳无 App 译音；保留录播格式与声道信息，不仅看 UI |
| SIDE-02 | 选择右耳，重复 SIDE-01 | 左耳无 App 译音 |
| SIDE-03 | 实际录播路由只有单声道，选择左/右耳 | 明确阻止单耳模式；只有用户主动选双耳才允许继续 |
| SIDE-04 | 开启系统单声道音频、改变左右平衡、切换空间音频 | 不宣称严格耳侧隔离；应用应提示/阻止已知冲突设置，不能检测的设置纳入用户校准 |
| SIDE-05 | 系统固定左/右麦克风，再切换远场 | 记录实际结果。不得将处理后音频推断为仅来自一个物理麦克风 |
| ROUTE-01 | 播报时取下、收盒、断开耳机 | 立即停止录音与播放，手机扬声器不续播 |
| ROUTE-02 | 翻译中更换到另一副耳机或车载蓝牙 | 会话暂停/失败关闭；不自动在新路由继续 |
| ROUTE-03 | 系统自动切换 AirPods 到另一设备，再切回 | 不播放上个会话积压内容；用户重新开始后重新校验能力 |
| PRIV-01 | 首次拒绝麦克风权限、之后在设置中授权 | 提示正确；重新开始可恢复，不出现假录音状态 |
| PRIV-02 | 停止会话、清空会话、退出并重新启动 | 不保留原始录音和文本；应用日志不输出原文或译文 |
| PRIV-03 | 资源已安装，开飞行模式后开启蓝牙 | 可以测试全链路离线；若失败必须明确提示，不能默默联网回退 |

## P0：生命周期和并发

| 编号 | 操作 | 预期结果 / 证据 |
|---|---|---|
| LIFE-01 | 准备模型/等待权限时按停止，再立即开始 | 旧任务不会启动录音或覆盖新会话状态 |
| LIFE-02 | 翻译进行中按暂停 | 录音停止、待译/待播队列取消，不出现迟到的语音 |
| LIFE-03 | TTS 合成中/首个 buffer 到达前按停止 | 所有回调失效，耳机不继续播报 |
| LIFE-04 | 连续快速开始/暂停/结束十轮 | 无重复 tap、重复结果流、悬空任务或崩溃 |
| LIFE-05 | 活跃会话期间修改语言/耳侧 | 禁止直接改动，或先完整终止旧会话；旧译文不能进入新语言会话 |
| LIFE-06 | 来电、Siri、闹钟等音频中断 | 状态明确暂停；结束中断不擅自恢复录音，不清空用户需要查看的已完成字幕 |
| LIFE-07 | 锁屏 10 分钟，继续有人讲话 | 记录实际连续性和延迟；若后台不支持，不能宣称锁屏运行已验收 |
| LIFE-08 | 播放/识别中触发音频媒体服务重置 | 安全停止；下次开始能重建音频引擎与路由 |
| FLOW-01 | 连续快速讲话，翻译/播报比输入慢 | 队列有界；过载显式暂停/报错，不能静默丢句并继续显示正常 |
| FLOW-02 | 超长连续发言且不暂停 | 测量最终识别片段迟迟不提交的情况；不能将终句转写误称固定低延迟同声译 |
| FLOW-03 | 用同样文字连续说两次 | 两次独立语音都被处理；不能按全文去重误删第二次 |
| FLOW-04 | 模型对同一时间范围给多次临时结果 | 字幕可更新，语音只播稳定/最终片段一次 |

## 翻译与听感测试

语言方向：中文→英语、英语→中文、中文→日语、日语→中文、英语→日语、日语→英语。每个方向至少包含短句、长句、否定、日期/时间、金额、数字单位、专名、中途修正、停顿与多人重叠。不要只用固定示例句。

环境：安静室内、咖啡馆背景声、轻微风噪。双耳佩戴、手机放口袋，测试说话者位于前方和侧方，距离约 1 米、2 米。记录手机放口袋与放桌面作为对照，不改变正式收音来源。

- 远场效果：人工核对录入文本能否保留对方意思，并统计自身说话是否被错误翻译。
- 串音：播报译文时继续对话，检查译音是否再次进入识别形成循环。
- 原声与译声重叠：记录可理解性，不把“另一耳静音”当成自动通透。
- 单人目标：多人同时说话属于未解决场景，记录失败而非推测系统能选中目标人。
- 错误记录：分开统计识别错、翻译错、播报错、漏译、增译，避免用整体主观满意度掩盖原因。

## 延迟与长时稳定性

每个方向至少采集 30 个语义片段，记录：源语音开始、源片段结束、最终识别、译文完成、首个合成 buffer、耳机实际出声。设备内部计时不能替代实际蓝牙出声时间；后者需要外部录音/录像测量。

- 报告中位数、P95 和最差值，同时报告整体滞后与片段末尾之后的等待。
- 连续讲话 10 分钟检查积压是否增长。
- 连续运行 60 分钟记录耗电、发热、内存、断流、重连与系统资源错误。
- 原先讨论的 1.5–3 秒属于目标，不是验收前可宣传的性能。
