# 低延迟、快语速与口音评估

状态：**评估方案已准备，尚无本轮真机性能或识别质量结果。** 1.5–3 秒是工程目标，不是实测值。CI 编译或单元测试不能证明 AirPods 的收音、口音准确率或耳机出声延迟。

## 1. 要验证的改进

| 假设 | 配对对照 | 必须同时观察的代价 |
| --- | --- | --- |
| 稳定前缀能更早给出可用译文 | 同一素材：最终结果路径 vs 提前提交路径 | 早提交错误、后续修订、数字/否定错误、重复和漏译 |
| 翻译与播放并行能减少积压 | 同一素材与语速：串行基线 vs 并行实现 | 顺序、取消、字幕完整度、过时译音和跳过播报 |
| 选择合适地区模型可能改善某些发音 | 同一说话人素材：默认 locale vs 实际支持的候选 locale | 总体 CER/WER、专名、别的说话人退化；地区选择不是口音识别 |
| 字幕优先能避免快语速时彻底失去信息 | 同一快语速长段：不追赶 vs 有界跳过过时待播音频 | 跳过比例与清晰标记；不能以漏播换来的低延迟冒称完整听译 |

基线必须固定提交、配置、系统和模型资源版本。本轮前一提交 `9fc4c4234dc561ee8fdc96d566e497e8fb5e32f8` 可作为候选基线，只有实际构建并运行后才有基线结果。记录本轮测试提交，避免拿不同设备、不同文本或不同声学条件比较。

## 2. 素材与受试设置

`evaluation/recording_prompts.jsonl` 是人工编写的**录音脚本**，没有音频、说话人、模型输出或成绩；24 条脚本覆盖中文、英语、日语，每种语言 8 条。`evaluation/README.md` 说明录制与标注过程。`evaluation/run_template.json` 是空结果模板，所有结果值初始为空。

先进行小规模冒烟：每语言一个说话人，8 条脚本各录正常/快速两次，共 48 段。需要对口音作初步比较时，扩展至每语言至少 3 位不同自然发音的说话人，每条录正常、约个人正常速度 1.25 倍、约 1.5 倍，共 216 段。倍数是录制指导，最终以测得速率分桶，不能把人为变速音频当作自然快语速语料。

由说话人自行描述日常地区发音或第二语言背景，可留空。不要根据身份推断口音，也不要让同一人模仿其他地区来替代真实多说话人样本。模型支持列表里没有对应地区时记录为“不支持该候选”，不伪造设置。

至少包含安静室内、固定背景噪声，以及前方 1 米/2 米。每次只改变一个主要变量。用户双耳佩戴、手机放口袋是目标场景；手机桌面收音只作为另列的对照。

## 3. 两层测试，避免混淆

1. **识别与调度可重复测试：** 用相同的已获同意的录音送入可用的测试入口，或通过固定扬声器位置/音量重复播放。后者同时含扬声器声学影响，报告中必须注明。此层适合比较识别文本、提交次数、修订和队列。
2. **实际佩戴端到端测试：** 人在指定位置自然讲话，佩戴者确认目标耳播报，并使用统一时基记录源音频与耳机实际声音。不得将屏幕录像中的字幕出现时间、TTS 调用时间或音频 buffer 入队时间当作出声时间。暂时无法录到耳机声音时，声学延迟标为“未测”，只报告软件处理时间。

同一素材至少重复 3 次；冷启动/资源准备、热启动分别记录。运行顺序交替或随机化，避免热状态、缓存、练习效应只利于新版本。iPhone 17/iOS 27.0.1 为用户主设备，iOS 26.0/26.1 的兼容备用路径与 iOS 26.2+ 远场路径分别记录。

## 4. 时间戳与延迟口径

对每个已提交语义片段保存以下测试标注；生产运行不应因此默认持久化对话内容。

| 字段 | 意义 |
| --- | --- |
| `source_start_ms` / `source_end_ms` | 人工参考中与此片段对应的源语音起止；多次早提交须映射到相应子片段 |
| `first_partial_ms` | 第一个包含该内容的识别草稿抵达 |
| `commit_ms` | 决定不可再当普通草稿处理的时刻 |
| `translation_start_ms` / `translation_end_ms` | 该片段翻译执行起止 |
| `tts_ready_ms` | 首个合成音频可用时刻；不是出声时刻 |
| `audible_start_ms` / `audible_end_ms` | 耳机实际译音起止，未测则为空 |
| `revision_ms` | 已提交内容收到冲突修订时刻，无修订则为空 |

关键口径：

- **片段结束至首译音：** `audible_start_ms - source_end_ms`。提前提交可能为负，原样保留，不截成零。
- **源片段开始至首译音：** `audible_start_ms - source_start_ms`，反映用户实际等了多长时间。
- **软件文本处理：** `translation_end_ms - commit_ms`，只能称为软件指标。
- **持续落后：** 每 30 秒记录当前播报所对应的源语音时间，与当前源时间差；观察 10 分钟趋势。
- **热启动目标：** 清晰近距离讲话下，片段结束至首译音中位数争取 1.5–3 秒、P95 不超过 5 秒。该目标不覆盖所有口音/噪声，也不替代质量门槛。

每个条件报告样本数、完成数、失败/跳过数、中位数与 P95；小样本明确标为探索性。只有播放成功的片段有声学延迟，必须在同一表中报告跳过率，禁止只展示成功片段以隐藏漏播。

## 5. 质量、完整度和修订

| 指标 | 定义与标注 |
| --- | --- |
| 英语 WER | 对人工校正的逐字转录计算替换+删除+插入除以参考词数；固定大小写、标点、数字规范化规则 |
| 中文/日语 CER | 对人工逐字转录计算字符编辑距离除以参考字符数；去除空白和标点，保留数字及否定词。不得直接跨语言比较 CER 与 WER |
| 关键意思错误 | 双语人工逐项核对脚本的 `meaning_checks`；特别标注否定、数量、时间、对象归属和自我修正错误 |
| 提交修订率 | 后续识别与已提前提交内容发生实质冲突的片段数 / 提前提交片段数；数字或否定变化不能仅按字符串相似视为无害 |
| 提前误播 | 错误早提交已经实际播出的次数，以及是否给用户可见修正；未播出的撤回另列 |
| 字幕覆盖 | 参考信息点在最终可见字幕中保留的比例；“字幕有200条”不是语义完整证明 |
| 漏播/跳过 | 已产生译文但未播报、主动跳过、取消中断分别计数；同一片段不能同时计为已完整播报 |
| 重复播报 | 相同源音频范围被无意再次播报的次数；说话人真实重复不算系统重复 |

低延迟模式必须报告准确率代价；修订标记不是让错误播报无限增加的免责方式。否定/数字反转、修订后无标记、输出乱序、旧会话译音混入、静默漏播是阻断问题，应修复后重测。

## 6. 口音优化的真实边界

`SpeechTranscriber.supportedLocales` 是运行时地区资源列表，包含可下载但未安装的模型。选择候选后应记录实际 `selectedLocales` 或配置 locale，不能只记录 UI 显示值。[官方地区列表](https://developer.apple.com/documentation/speech/speechtranscriber/supportedlocales)

苹果的 `AnalysisContext.contextualStrings` 文档针对 `DictationTranscriber` 描述词语提示。本轮继续使用 `SpeechTranscriber` 时，不把该 API 当作已生效的口音或术语增强；若将来引入 Dictation 路径，须独立比较速度、质量和词语提示效果。[官方词语提示说明](https://developer.apple.com/documentation/speech/analysiscontext/contextualstrings)

口音改善的结论必须限定到实际测试的说话人、地区候选、语言和设备版本。没有录音结果时只能声明“增加可选地区识别配置”，不能声明“口音识别准确率已提高”。
